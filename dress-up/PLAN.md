# 옷입히기 게임 계획서

여자 캐릭터 한 명에게 옷을 입혀 보는 게임. 화면 오른쪽에 옷을 진열해 두고 눌러서 입힌다. `dress-up/index.html` 한 장으로 만든다.

## 1. 요구사항

- 캐릭터는 여자 하나.
- 옷은 **드레스**, **상의**, **하의**로 나누어 화면 **오른쪽**에 진열한다.
- 진열된 옷을 누르면 캐릭터가 입는다.
- 파일은 `index.html` 하나. 외부 라이브러리·외부 이미지·외부 글꼴·분석 도구를 쓰지 않고, 외부로 연결하거나 저장하지 않는다.

## 2. 명세에 없어서 정한 점

| 항목 | 정한 것 | 이유 |
| --- | --- | --- |
| 위치 | 오른쪽 진열대는 화면이 넓을 때의 배치다. 좁은 화면(폰 세로)에서는 캐릭터 아래로 내려온다. | 폰에서 캐릭터가 너무 작아지는 것을 막기 위해. |
| 입는 규칙 | 드레스를 입으면 상의·하의가 벗겨지고, 상의나 하의를 입으면 드레스가 벗겨진다. 상의와 하의는 함께 입을 수 있다. | 드레스는 상하의를 겸하는 옷이라서. |
| 벗기 | 입은 옷을 다시 누르면 벗는다. 「기본 차림으로」 버튼은 모두 벗고 처음 상태로 돌린다. | 별도 벗기 버튼 없이도 되도록. |
| 기본 차림 | 아무것도 안 입은 상태는 흰 속옷(민소매 속옷 + 짧은 속바지) 차림이다. | 어린이도 볼 수 있는 모습으로. |
| 종류와 수 | 드레스 4벌, 상의 4벌, 하의 4벌, 총 12벌. | 요청한 종류를 고르게 채우는 분량. |
| 그림 | 캐릭터와 옷은 전부 직접 그린 벡터 도형(SVG)이다. 외부 이미지·캐릭터 도용 없음. | 외부 파일 없이 한 장으로 만들기 위해. |
| 위치 | 오목과 같은 저장소의 `dress-up/` 폴더. 오목은 그대로 둔다. | 게임을 추가하는 방식. |

신발, 액세서리, 머리 모양 바꾸기는 요청에 없어 넣지 않는다.

## 3. 구성

```
dress-up/index.html   화면 + 규칙 + 그림 데이터 (한 파일)
dress-up/PLAN.md      이 문서
tests/                자동 시험 (오목과 같은 폴더)
```

`dress-up/index.html` 안은 세 블록으로 나눈다.

1. `<script id="outfit-logic">`: 규칙. 화면 요소를 쓰지 않는 순수 함수. 옷 목록(`ITEMS`), `wear`, `describe`, `emptyOutfit`. 상태는 바꾸지 않고 새 상태를 돌려준다.
2. `<script id="dress-art">`: 그림 데이터. 캐릭터와 옷 12벌의 도형 목록. 화면 요소를 쓰지 않는 순수 데이터.
3. `<script id="dress-ui">`: 그림 데이터로 SVG를 만들고 진열대와 클릭 처리를 한다. 규칙은 판단하지 않는다.

SVG 도형은 `createElementNS`로 하나씩 만든다(`innerHTML`을 쓰지 않는다).

## 4. 화면

- 왼쪽: 캐릭터가 서 있는 무대. 입힌 옷이 겹쳐 그려진다(속옷 → 하의 → 상의 → 드레스 순으로 덮음).
- 오른쪽: 「드레스」「상의」「하의」 세 칸의 진열대. 옷마다 작은 그림과 이름이 있고, 입고 있는 옷은 테두리로 표시한다.
- 위에 상태 한 줄: "입은 옷: 분홍 원피스" 또는 "기본 차림".
- 키보드로도 옷 버튼에 Tab으로 가서 Enter·Space로 입힐 수 있다.
- 어두운 모드 설정을 따른다. 글꼴은 기기 기본 글꼴만 쓴다.

## 5. 시험 계획

- 규칙: 상의+하의 같이 입기, 드레스가 상하의를 벗김, 상의·하의가 드레스를 벗김, 같은 옷 다시 누르면 벗음, 같은 종류 교체, 모르는 옷은 무시, 원래 상태를 바꾸지 않음, 설명 문구.
- 옷 목록: 종류 3개, 옷 12벌, 아이디 중복 없음.
- 그림 데이터: 모든 옷에 그림이 있고 남는 그림이 없음, 허용한 도형 태그만 사용, 외부 참조(`href`, `url()`) 없음, 좌표가 캐릭터 그림 영역 안에 있음.
- 제약 점검: 오목과 옷입히기 두 페이지 모두 외부 주소·글꼴·분석 코드·저장·전송 API가 없고 외부 연결을 막는 CSP가 있음.
- 화면은 헤드리스 Chrome으로 실제로 눌러 보고 스크린샷으로 모양을 확인한다.

2. 규칙 + 그림 데이터 + 시험

5. 전체 시험 통과 확인 후 PR (오목 PR #2 위에 쌓는다)
